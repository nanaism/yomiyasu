# 限界と確かめた範囲

README の[限界](../README.md#限界)の節を詳しく書いたものです。

付属の検査（lint と diff、2つをまとめて実行する check）は、決まった形を拾うものです。意味が保たれたかと読みやすいかは、元の文と読み比べて人が確かめてください。候補が出なくても、変わった箇所は全文差分に出ます。以下は 2.0.0 の時点で分かっている限界で、細かい形は各項目の「細かい形」を開くと読めます。2.0.1 と 2.0.2 は検査の出力を変えていないので、検査で拾えない形も、正しく推敲しても候補が出る形も 2.0.0 と同じです。

## 意味が変わる恐れに出ない形

原文にない担当者や動作主を主語や通知先に足した推敲（容量が一割を切ったら知らせる → 容量が一割を切ったら、保守担当者に知らせる）は、全文差分と「元の文にない語」には出ますが、意味が変わる恐れには出ません。上の tests/corpus の古い推敲の出力では、意味が変わった箇所の多くがこの形でした。

<summary>ほかに出ない形</summary>

できる → している、評価の語（容易）や表題の（下書き）を消した推敲、範囲を言い換えた推敲（一律に → 全部の口に同じ設定で）、する側と受ける側を替えた推敲、「にくい」を否定にした推敲（追いにくくなっています → 追えません）も出ません。
</details>

## 数値

表記だけの違い（漢数字と算用数字、範囲・日付・時刻の書き方など）は候補にしないよう作っていますが、万と億を含む数の換算（一万円 → 1万円）、「.」で区切った日付、時刻の「:00」、「0円 → 無料」などは、値が同じでも候補に出て、`--fail-on=meaning-risk` に数えます。逆に、範囲の端の値を別の値として書き直した形、平仮名の数（ひとつ、ふたり）を足しただけ・消しただけの書き換え、助数詞の一覧にない語（冊、点、票）の数の変化などは拾えません。

<details>
<summary>細かい形（正しい推敲にも出る形）</summary>

万と億を含む数の換算（一万円 → 1万円）、「.」で区切った日付（2026.10.13 → 2026年10月13日）、時刻の「:00」（9:00 → 9時）、「v2.0 → バージョン2.0」「0円 → 無料」、「一度」と漢数字の並び（一度 → 1度、第三四半期 → 第3四半期、三四人 → 3〜4人）、前に何もない「一時」（一時三十分 → 1時30分。一時的の「一時」と分けられない）、「じゅうぶん」と分けられない「十分」（一回十分です → 1回10分です、八時間十分働いた → 8時間10分働いた）は、値が同じでも候補になります。直前が漢字の漢数字（夜一人で）は数として取らないので、助詞を足しただけ（夜に一人で）でも候補になります。回数を言わなくした書き換え（月一回 → 毎月）、「一人十分の量 → 一人あたり十分な量」、「層を1枚挟む → 層を作って前に置く」は、消えた数値として出ます。数を言わない語を数字で言い直した推敲（一意 → 1つ、倍々 → 2倍ずつ、単体 → 1件ずつ、集約 → 1件にまとめ）と、助数詞だけを替えた推敲（3〜4本 → 3〜4回）も候補になり、--fail-on に数えます。序数の「1つ目 → 最初の」は消えた数値、「一つずつ → 一枚ずつ」は元にない数値になります。同じ単位の数の前後を入れ替えただけの推敲（ひとりで3人分を食べた → 3人分をひとりで食べた）は、並びの候補になります。「ずつ」のあとに動詞がない文は、相手の文のどこかに「複数」「いくつか」があれば、順番に、と言い換えた正しい推敲（質問は一つずつどうぞ → 質問は順番にどうぞ。複数ある方も順番にお願いします）でも消えた数値になります。「一つずつ」の動詞や「一つの」の名詞を言い換えた1つの文では、主題と同じ語を主語にした節（似た質問が複数届いたら一覧にします）、主語のない節（版ごとに別々の名前を付けます）、送り仮名の途中で切れる主語の節（問い合わせが複数重なれば）にある 複数・いくつ・別々 を数えるので、別の物の数を言い換えただけの推敲でも消えた数値になります。数の主張が同じ語（順に）があっても、前から数えていた語（まとめて）が別の述語に付けば、消えた数値になります（ファイルは一つずつ確認する → ファイルを順に見て、結果はまとめて送る）。
</details>

<details>
<summary>細かい形（拾えない形）</summary>

範囲の端の値を、同じ文の別の値として書き直した形（3〜5日かかる → 5日で終え、予備に3日をとる）、数量を言っていない漢数字の「一つ」や期間の値を言わなくなった書き換え（今日一日で終える → 今日から数日で終える）、2つの文をまとめたときに組にならなかった文の「一つずつ」の変化、読点を挟まずに別の述語の打ち消しが続く形（一つずつ行う → 並列で行い遅延を出さない）、前に何もない「一時十分に → 一時に」、助数詞の一覧にない語（一人一票 → 一人二票。冊、点も同じ）と「お一人様一つ」の数の変化は、候補に出ません。数量を言っていない「一つ」と同じ扱いなので、「もう1つ」「1つの」を足した・消した書き換えは、数を限る意味でも拾いません（理由がある → もう1つ理由がある、同時に使える端末は1つの端末だけです → 同時に使える端末に制限はありません。「1つの」を含む文を消した推敲も同じです。資料から書いた最終稿の「1つの画面にまとめました」も、資料にない数値にしません）。平仮名の数は相手の文に同じ単位の値がないと比べないので、足しただけ・消しただけの書き換え（会議室はふたつある → 会議室がある）と、「ふたつしか」「ひとりだけ」「ふたりまで」「ふたつずつ」を言い換えた書き換えは拾いません（漢数字なら拾います）。資料から書いたときの照合でも、平仮名の数は資料の値と違っても候補にしません（参考の行に資料の値が出ます）。「に」「で」のすぐあとの「いつつ」は数として取らないので、「箱にいつつ入れる」の数の書き換えも拾いません。文を分けて「複数」「いくつでも」を別の文に置いた推敲（ファイルは一つずつ送ってください → ファイルを送ってください。複数あってもかまいません）と、「一つの」の名詞のある節から離して「別々」を置いた推敲（鍵は一つの金庫にしまう → 鍵は別々の場所にある金庫にしまう）は拾いません。数値の直前の2字とあとの語が同じ入れ替え（上限は10GB、下限は500MB → 上限は500MB、下限は10GB）、直前が読点の数の入れ替え（設計に3日、5時間を試験に充てる → 設計に5時間、3日を試験に充てる）、同じ助詞のあとの「約」の数の入れ替え（設計に約3日、試験に約5時間 → 設計に約5時間、試験に約3日）は、並びの候補にしません。
</details>

## 否定

語ごと言い換えた否定（確認します → 確かめません）は、否定の候補に出ません。文を分け、否定を別の言い方で次の文に移した推敲（…形に変えてから、抜けた通知の調査は発生していません → …ています。この形に変えてから、抜けた通知を調べる事態は起きていません）は、正しい推敲でも否定の候補になり、--fail-on に数えます。

## 否定対比の主張の逆転

平仮名で始まる語（お知らせ）と漢字1字の語は、否定された語として取りません。見出しや「Aは使わず」の文、一覧にない言い方で A を後ろへ回した推敲などでは、正しい推敲にも候補が出たり、逆転を見逃したりします。否定した側を消しただけの推敲は候補にしません。逆転は `--fail-on` に数えないので、候補が出たら、A が目的や優先の側に移ったかを読んで決めてください。

<details>
<summary>細かい形</summary>

「お知らせ」のように平仮名で始まる語と、漢字1字の語（人ではなく仕組み）は、否定された語として取りません。「Aも含めて」の形も拾いません。見出しの行と「Aは使わず」「Aはせず」の文では、A を足しただけの書き換え（外部委託はせず、社内で作ることを最優先にします → 社内で作ることを最優先にし、外部委託も使います）と、別の節の語が A を指す書き換え（表計算は使わず → 表計算で入力し、これを最優先の手順にします）を拾いません。一方、一覧にない言い方で A を後ろへ回した推敲（来期に回す、Aに手を付けるのは見送る、Aは優先順位を下げる）は、正しい推敲でも候補に出ることがあります。下げる語は A のすぐあとに続く形だけを見て、「そのあとに回す」は平仮名の書き方だけを見るので、読点を挟んだ形（Aは、その次に見る）や「その後に回す」「次に見る」も、正しい推敲で候補に出ます。別の名詞のあとの「は後に回す」（品質を最優先にして速度は後に回す）の逆転は拾いません。主題の句（最優先は、大事なのは など）のあとに、置き換え先を言わずに A を変える言い方を置いた正しい推敲（## 大事なのは、会議を最小限にして文書で決めること）は、原文で肯定した側の語を使っていても逆転の候補に出ます。重みの語だけの句（まず、第一に など）のあとでも、原文で肯定した側の語を使わずに A を変える・取り除く・調べる言い方（減らす、絞る、洗い出す、時間を測る、A を別のものにする・別のものに変える。## まず、手作業を洗い出す）は、正しい推敲でも候補に出ます。読点を挟んで置き換える言い方（Aを、B に置き換える）も同じです。本文の「Aではなく」の推敲は、重みの語が文のどこにあっても見るので、原文で肯定した側の語を使った正しい推敲（まず、手作業を自動化する）でも候補に出ます。一方、重みの語だけの句のあとで A と B の語を両方使った逆転（## 会議ではなく文書で決める → ## まず、会議で決めて文書で知らせる）は拾いません。B を廃止する・見送る・控える・禁止する・なくす・頼らない、と言う逆転と、B より A を優先する・B を後回しにする、と比べて下げる逆転（## まず、会議を文書より優先する）も拾いません。逆に、置き換え先や A を使う句が一覧にない言い方（試作版を正式版に移行する、クラウドを主にした構成に切り替える）は A を下げた形とみなすので、A を採った推敲を見逃すことがあります。逆転は --fail-on には数えません。

否定した側を消しただけの推敲（AではなくB → B、Aに任せず → 消す）と、「Aにすぎず」の言い換えは、候補にしません（逆転だけを見る検査です）。
</details>

## 文の種類の印と気持ちの語

依頼を前置きする文を依頼の文にした推敲（お願いしたいことは3点あります → 次の3点をお願いします）と、結果を言う文を義務の文にした推敲（修正につながります → 修正しなければなりません）は、文の種類の候補になり、--fail-on に数えます。

元にない気持ちの語の検査（一覧は `references/lists/feelings.txt`）は、一覧の語だけを見ます。同じ語が原文のどこかにあれば、別の所に足しても出ません。「売上が前年より落ち込んだ」のように間に語が入る形と、「苦しい言い訳」のような気持ちでない使い方は、候補に出ます。

## 文体の硬化と勢い

変わった文が1つだけの文書では、1文の条件に当たらない小さな硬化は出ません。勢いは、評価の語を短く重ねる型を1文にした推敲と、一覧にない褒め言葉の繰り返しを減らした推敲を拾いません。種類を指定しないと、定型の結びを消した推敲のような正しい直しも、勢いの見直し候補になります。

<details>
<summary>細かい形</summary>

promo でも、箇条書きの太字の行（- **…**）は見出しに数えません。ほかの種類では、番号つき項目の行と太字だけの行も数えません。評価の語を短く重ねる型（安い。うまい。早い。）を1文にした推敲と、強める語の一覧にない褒め言葉（絶品など）の繰り返しをまとめて減らした推敲は拾いません（紹介記事ではどちらも残す決まりなので、読み比べて確かめます）。種類を付けないときは、AIの定型の結び（「いかがでしたか？」「ぜひご活用ください」）を消した推敲や、技術文書の「！」を句点にした推敲のような正しい直しも、見直し候補になります。
</details>

## 慎重な言い方・引用の印・宛名・敬語の度合い

慎重な言い方は、一覧（`references/lists/hedges.txt`）の7つの語と同じ文字の並びだけを見るので、「示唆した」「示唆される」のように形の変わった語が減っても拾いません。引用の印は、数字の角括弧と、著者と年をまとめた括弧の形だけで、本文に著者を書いた形（山田 (2020) によると）の著者の変化と、引用の印を別の文へ動かした推敲は拾いません。英字の著者は年の前に「,」か「et al.」があるものだけを見ます（(Smith 2019) は拾いません。(Windows 2000) のような製品名と年の括弧を引用と取らないためです）。漢字の名前と年の括弧（(東京 1998) など）は引用として見ます。符号は、直前が漢字や片仮名のときは見ません（「10月-12月」の範囲を負の数と取らないためで、「前年比-5%」の符号も見ません）。宛名は行の頭と宛先の欄のものだけを見ます。敬語の度合いは文書全体の割合で比べるので、短いメールでは1文の違いでも候補になり、長い文書では1文の変化を拾いません。「ください」も「くださる」に数えるので、「〜いただけますでしょうか」を「〜してください」にしても候補は出ません。文末の割合は「です・ます」と「だ・である」の文だけで数えるので、チャットの口語（〜かも、〜しときます）を「です・ます」にそろえても候補は出ません。二重敬語を正しく直すと（ご確認させていただきました → 確認いたしました）、敬語の数が減って候補が出ます。mail と paper の推敲の指針（`references/doc-types/mail.md`、`paper.md`）は、モデルに推敲させて結果を測っていません。tests/corpus には実際のメールと論文がほとんどなく、正しい推敲の48組で3つの検査の候補が0件だったことから、拾い漏れが少ないとは言えません。

## 書き手と読み手

敬語を上げる形は、同じ動詞に「お・ご」を付けた形と、人がふつう書く言い回しのどちらかを選びます。どちらが自然かは文脈で変わり、2つのモデルがそろって自然とはしなかった言い換えも残ります（測った原稿の取引先への依頼で、Claude Code の2回の20か所のうち3か所）。書き手の主語を補う文は、原文に書き手の一人称がある文書だけで、チームや会社の決定とも読める文には補いません。依頼で関係を伝えなかったときは、宛名から社外あてと分かっても敬語を上げません。

## 状態の語・約束・因果・評価と一般化

どれも語の表と文の組で見るので、表にない言い回しは拾いません。合成の組で確かめると、状態の語が消えた書き換えの9割、原文にない約束・誓いの足しの8割を数えました。原文にない因果の足しは、12組のうち9組で候補が出ました（数えない因果の候補が8組、ほかの数える候補が1組）。

原文にない評価の語（改善、向上、好評、大切）と、一般化・勧めの足し（他の窓口でも同様に、望ましい、とよいでしょう）は、diff では拾いません。語の表で試しましたが、合成の組で評価の足しは14組のうち0組、一般化・勧めの足しは14組のうち6組しか出せず（目安は7割）、配る diff には入れませんでした。表にない形容（分かりやすい、洗練された、盛況、適切、十分に小さい）や、表にない勧めの形（一般的です、どの店舗でも、種類を問わず）が多かったためです。「すべきです」のように文の種類の印（義務）が変わる足しは、文の種類の印の候補として出ることがあります。原文にない良し悪しの判断や勧めを足していないかは、読んで確かめてください（`references/review-points.md`）。

<details>
<summary>拾わない形と、正しい推敲にも出る形</summary>

- 状態の語: 表にない言い方（「照合はまだです」のように否定の述語のない「まだ」、「本人の確認待ちです」のように表にない名詞につく「待ち」、「未取得」のように表にない「未〜」）は見ません。近い家族の語への言い換え（調査中 → 原因は分かっていません）は、状態が残ったとみなします。表にない「未〜」に言い換えた正しい推敲（承認はまだ受けていない → 承認は未取得です）は、状態が消えたとして数えます。「〜中、」は、同じ節に「は」「が」の主題があるときだけ見ます。
- 約束: 誰の行為かは主語の語でしか見ません。書き手でない人の約束を、主語を書かずに足した推敲は、書き手の約束として出ます。謙譲の形も未来の印も書き手の主語もない「〜します」は、約束でも数えない候補にとどめます（お支払いの期限は1週間延ばします）。組になった原文の文に未来の述語があれば、別の行為の約束でも言い換えとみなして打ち消します（資料を読みます → 資料を破棄します）。済んだ行為を未来の約束にした書き換え（送りました → 送ります）と、他人の行為を書き手の行為にした書き換えは見ません。「伺います」「行います」のように「い」で終わる動詞の「〜ます」は、状態の述語と区別できず、拾いません。依頼や資料に書いてある約束を足したときも数えます。「当方では分かりかねます」「〜をお勧めします」は、約束ではないのに約束として数えます（正しい推敲でも `--fail-on` で終了コード1になります）。
- 因果: 原文の1文の「〜し、」「〜て」を「ため」「ので」と語にしただけの形は出しません。「〜をきっかけに」「〜した影響で」「〜した効果で」のような表にないつなぎは出しません。
</details>

## 事実の補いと資料の照合

`--fact-gaps` の候補は一部だけです。拾うのは、程度の語だけの文、変わる前と後の値がない変化、効果だけの文、中身の見えない比喩の4つで、主語の抜けは拾いません。数値、確度の語、ぼかした語、書き手が省いた印、決意や抱負の結びのある文と、問い、見出し、表、コード、引用も見ません。候補に出なかった所にも、中身の書かれていない所はあります。

<details>
<summary>候補を測った数</summary>

- 一覧を合わせ込むのに使った合成の文では、出てほしい35文のすべてに出て、残す31文には出ませんでした。
- 合わせ込んだあとに書いた合成の文では、出てほしい25文のうち17文に出て、残す21文には出ず、境目の4文のうち2文に出ました。拾えなかった8文は「待ち時間がぐっと減りました」「検索の高速化を実現しました」「費用を抑えました」「安定稼働に大きく貢献します」「挙動を見直しました」「体験を一段と高めます」「開発の道が開けました」「黙って失敗していました」のような文です。
- 評価用に AI に書かせた文のうち、残す例として集めた61文と、tests/corpus の human の16本（作者の記事の抜粋8本と、人の文らしく AI が書いた例文8本）には出ませんでした。tests/corpus は一覧を合わせ込むのに使った群なので、取っておきの結果ではありません。
- 6万字の文書で候補を探す時間は、Python 3.14.5 で約0.03秒、3.9.6 で約0.04秒でした（3回）。
</details>

- 照合の「資料に基づく補足の候補」と「単位のない数とだけ一致」は、資料のその行に同じ値があることを示すだけで、根拠であることも正しいことも示しません。設定の `retry_wait = 3` を回数の「3回」に使う、失敗した回と成功した回のログの時間を変更の前と後にする、といった取り違えは、道具では止められません。
- 照らすのは数値、名前、語、確度の語だけで、主張、条件、担当が資料どおりかは判定しません。
- 抜き書き（`.material.txt`）の中身が、開いたファイルやコマンドの出力と同じかは確かめません。
- 抜き書きも、ほかの資料と同じく記録の `.yomiyasu/inputs/` に写しが残ります。残したくないときは `--no-record` を付けます。
- 資料のファイルに `<<<yomiyasu:` で始まる行があり、正しい資料の区切りの行でなければ、`--material` でも終了コード2で止まります。
- スキルが補った事実が正しいか、問いにすべき所を問いにしたかは、道具では判定しません。

## lint の `<details>` と check

lint が箇条書きの比率から外すのは、行頭から書いた `<details>` と `</details>` の組の中だけです。

<details>
<summary>細かい形</summary>

行頭から書いた開きと閉じが組になったときだけ見ます。段落の途中に書いた `<details>`、閉じていない `<details>`、引用の中の `<details>`、`:::details` のような Markdown の拡張の書き方は見ず、中の箇条書きを今までどおり数えます。`<details open>` も畳んだものと同じに扱います。ライブラリとして `lint_text()` を呼ぶときは、先頭の BOM を外した文字列を渡してください（BOM が残ると1行目の `<details>` を見ません。コマンドは BOM を外して読みます）。
</details>

本文に `<<<yomiyasu:` で始まる行がある文書は、`--stdin` では渡せません（ファイルで渡します）。2.0.1 で diff の照合を速くしたので、6万字の全面書き換えでも diff は2秒ほどで終わります（2.0.0 では約15分かかり、run の既定の `--timeout`（90秒）で partial になっていました）。ただ、次の2つの形はまだ時間がかかります。同じ形の文が並ぶ文書の全体を書き換えると、書き直した文と元の文の組を比べる所が文の数の2乗で伸びます（25万字の合成の文書で約10秒、49万字で約34秒）。70万字を超える全面書き換えでは、既定の `--timeout` を超えることがあります。句点のない長い1行（20万字ほど）も、既定の `--timeout` を超えることがあります。2.0.2 では1つの段落に崩れた太字が多い文書で lint と diff の太字の検査が崩れの数の2乗で伸びていたのと、1行に文と数値が多い文書で diff の数値の比べが伸びていたのを直しました（出力は 2.0.1 と同じです）。ただし、崩れた太字と同じ段落に `<` や `<br>`、閉じていないリンク、太字に続く URL があると、lint と diff の太字の検査は 2.0.1 と同じく崩れの数の2乗で伸びます（同じプロセスで lint を動かした CPU 時間で、1段落に1,000組で約3秒、どの組にも URL が続く形では約11秒）。
