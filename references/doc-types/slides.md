# スライド（slides）

あわせて読む: domains/tech.md か domains/business.md（中身で選ぶ）
lint で外す規則: bare_verb_chain、bold_label_list、cleft_list_ending、count_declaration、excess_list、short_summary_heading

## 1. 普通な書き方（直さない）

- 短い句や体言止めの見出しと箇条書き、ラベルと値の項目。
- 目次と「ポイントは3つです」、まとめのページ。
- 箇条で強調として選んだ「〜のは、A、B、C」の形（lint の cleft_list_ending はこの種類では外す）。
- `---` のページの区切り、Marp などの先頭の設定、話者のノート。
- スライドの前と後に付いた、依頼者あての前置きや注記（構成の説明、仮の値や仮の例の断り、誤記の補足、続けて作れるという申し出）。スライドの中身ではないので推敲せず、そのまま残す（slop-catalog.md 6章の「チャット応答の名残」として削らない）。要らなければ書き手が外す。中身から書き手に確かめたいことがあれば「書き手に確かめたい点」で尋ねる。

## 2. それでも直すもの

- 長い文の見出し。何を扱うページかが分かる短い項目名にする（SKILL.md「案内用の見出し」）。
- 縮めすぎた標語の見出し。補い方が1つに決まるときだけ補い、決まらなければ残して確かめる。
- この2つと見出しの読点は依頼で見出しの形（長さ、言い切り、番号、記号）や、まとめのページを指定されているときは直さず、その形とページを保つ（SKILL.md「案内用の見出し」）。
- 「速い。軽い。安い。」の型（lint の fragment_run はこの種類でも外さない）と絵文字。
- 見出しと1行の箇条の、間を作るだけの読点。見出しと箇条は一目で読むので、地の文なら残す読点でも、次の読点は外す: 文頭のつなぎの語のあと（だから、そこで、結局）、「振り返れば」「数字で言えば」のような決まった言い方のあと、文頭の長い時や場面の句のあと（その日のうちに、会議が終わるまでに）、短い主題や主語のあと（新しい手順では、大事なのは）、目的語の「を」のあと。lint の slide_comma が、この種類のときだけ候補を出す。
- 次の読点は残す: 逆接（のに、ても、けれども、ながらも、述語＋が）、条件（なら、たら、「〜ときは」「〜場合は」、「上司に言えば」のような「〜ば」）、理由や目的（ので、ために、ためには）、名詞の並び、「その夜、」「翌朝、」「始める前に、」のような短い時の句、主題のあとに別の主語が続く所（会議では、担当者が説明した。前の画面には、文字が小さいという声があった）、長い行で「〜ではなく」の否定と言い直しを分ける所、長い主語のあと、外すと掛かり先が変わる所、カギ括弧の中。

## 3. 長さと省略

- ページの数と順、ページの中の項目の順を変えない。説明の文をページに足さない。
- 1つの箇条は1行に収まる長さを保つ。体言止めと助詞の省略を残し、文にのばさない。
- 見出しの記号（#）がない文字（PowerPoint から写したもの）には見出しの規則を当てない。
- 新規作成では、スライドに番号を付ける。

## 4. 例（合成）

| 元 | 扱い |
|---|---|
| - キャッシュの期限を短縮 | 残す（体言止めの項目。「短縮しました。」にしない） |
| ## ポイントは3つです | 残す（目次のページ） |
| ## だから、引き継ぎの資料を先に作った | 読点を外す（## だから引き継ぎの資料を先に作った） |
| - その日のうちに、手順書を書き直した | 読点を外す（- その日のうちに手順書を書き直した） |
| - 急ぎなら、電話で連絡する | 残す（条件の読点） |
| - その夜、直す前と後を比べた | 残す（短い時の句の読点） |
| - 前の画面には、文字が小さいという声があった | 残す（主題のあとに別の主語が続く読点） |
| ## 速さは、信頼。 | 直す候補。何を扱うページかが分かる見出しに戻す。補い方が1つに決まらなければ直さずに確かめる。依頼で見出しの形を指定されていれば直さない |
