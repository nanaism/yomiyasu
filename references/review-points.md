# 検査の出力の見方と目視の点検

SKILL.md の Step 3 と Step 4 で `yomiyasu_check.py run` の出力の候補を確かめるときに読む。Python を実行できないときは4章の目視の点検に従う。

候補は直す指示ではなく、原文（新規作成では資料）に照らして確かめる箇所。候補を消すためだけに言い換えを繰り返さない。直すのは1回までで、直したら run をもう一度実行する（SKILL.md の Step 4）。候補が出ないことも、意味が保たれたことの証明ではない。lint は点数を出さない。候補の数を品質の合格点として扱わない。

## 1. 出力の始めの行

- 1行目は次にすることを示す。そのとおりに進める。lint、diff、資料との照合の候補が0件でも、文体の硬化と勢いの見直し候補があれば、1行目は「その節を原文と照らし」と案内するので、■ 文体の硬化 と ■ 勢い の節を原文と読み比べる。
- 2行目は状態の行（`yomiyasu-check:` で始まる行）。出力の「確認の記録」に写す。提出の前に verify を実行したときは、verify の出力の2行目を写す。
- 3行目は実行した検査の要約で、確認の記録の「実行した検査」に対応する。diff の「候補N件」には、文体の硬化と勢いの候補を数えない（次の2行と、それぞれの節に出る）。diff だけを実行したときも同じで、状態の行の末尾に「（文体の硬化と勢いの見直し候補 N件は下の節）」が添えられる（最後の状態の行では「上の節」）。
- 記録の行のあとに「硬化の検査: 候補なし」「勢いの検査: 参考1件」のような2行が出たら、値を確認の記録の同じ名前の行に写す（参考だけなら「参考N件」、見直し候補と参考が混ざれば「候補N件、参考M件」になる）。diff を実行しなかったときなど、この2行が出なければ、確認の記録にも2行を書かない。
- 続けて「慎重表現の検査」「値の検査」の行が出る（`--doc-type mail` のときは「敬語の検査」も）。値が「候補なし」でないとき（「候補N件」「意味が変わる恐れ N件」など）だけ、確認の記録の「勢いの検査」の行の下に、同じ名前と値で写す（- 値の検査: 候補1件）。「候補なし」なら写さない。値の検査の「意味が変わる恐れ N件」は、■ 意味が変わる恐れ に出た引用の書き方と数値の候補の数。文体の切り替えの候補があるときだけ「文体の検査: 候補N件」の行も出る。出たら同じ名前と値で写す。中身は2章の ■ 慎重な言い方、■ 動かしてはいけない値、■ 敬語の度合い、■ 文体の切り替え の節で確かめる。
- 続けて「見直し候補: 原文 N件 → 最終稿 M件」の行が出る（新規作成では「最終稿 M件」）。lint の規則に当たった数を前後で並べたもので、点数ではなく、増減は読みやすさの良し悪しを示さない。値を確認の記録の「見直し候補」の行に写す。

## 2. 出力の節ごとの見方

### ■ 直した箇所

全文差分と同じ組の元と後を、初めの10か所まで、長い所は60字ほどで切って並べた要約。意図しない変更がないかを先にここで見て、切った所と11か所目からは ■ 全文差分 で確かめる。案内の1行に「元と後で行の数が違う所」とあれば、別の段落どうしが並んでいることがあるので、全文差分で前後の組も読む。

### ■ 意味が変わる恐れ

数値、否定、「が」「を」などの入れ替え、問いの文、文の種類を表す語、コード・URL・引用、資料にない数値や名前が変わった箇所。原文と資料に照らし、意図しない変化は元に戻す。資料に基づく訂正なら残し、「事実の確かめ」に出典と書く（`references/fact-recovery.md` 4章）。

否定されていた語が、否定のない文に「目的」「重視」「まず」などの語と一緒に出た箇所（見出しと「Aは使わず」「Aはせず」では、A を肯定した節に出た箇所）と、「AだけでなくB」「AとB」のように B と並べて肯定された箇所（否定対比の逆転）もここに出る。否定対比を直したときに、否定していた側が目的や優先の側へ移っていないかを確かめ、移っていれば主張が逆になっているので原文の否定に戻す（rephrase-test.md 3章）。「まず、Aを減らす」「まず、Aを自動化する」のように A を減らす・変える推敲でも候補に出ることがあるので、A が目的や優先の側に移ったのか、減らす・変える側のままかを読んで決める（側が変わっていなければ、そのままでよい）。拾えない形もあるので、候補がなくても否定対比を直した箇所は読み比べる。

引用の書き方（[1]、(山田 2020) のような形）の変化もここに出て、`--fail-on=meaning-risk` に数える。著者が変わったときなどは「引用の書き方が変わった」と出る。番号や年だけの変化と、数字を含む引用を消した・足したときは、数値の候補として出ることがある。括弧の全角と半角、空白のような書き方だけの違いは出ない。どの主張をどの文献が支えるかが変わるので、原文の書き方に戻す。

確度の語の強さを、可能性 < 見込み・推量 < 予定 < 断定 < 確実 の順で比べた候補も出る。「見込み → 予定」「と思われる → 断定」のように、可能性や見込み・推量の主な慎重な語が消えた、またはより強い語に替わった書き換えは `--fail-on=meaning-risk` に数える。「予定」「見込み」は、述語として確かさを言うとき（する予定です、完了の見込みです）だけを見て、予定表や見込み客のような名詞は見ない。確度を弱めた書き換えと、「ことがある」「傾向」「検討」など数えない語だけの変化、「確実に」「必ず」を足した・消した変化、予定の言い切り（見直す予定です → 見直します。書き手の予定なら言い切ってよい）は見直し候補にとどめる。ただし文書の種類が formal、manual、proposal、pr、incident、paper、article のときは、「場合がある」「ことがある」を消して言い切った書き換えと、断定に「必ず」「確実に」などを足した書き換えを `--fail-on=meaning-risk` に数える（原文の文に「必須」「しなければならない」などの義務の語があるときの「必ず」は数えない）。許可（〜してよい、差し支えない、構わない）と能力（〜できる、可能だ）の言い方が、同じ文（分けた・つないだ文を含む）の中で消えた・増えた・ほかの言い方に替わった候補も出る。許可が消えた・増えた書き換えは、どの文書の種類でも `--fail-on=meaning-risk` に数える。能力が消えた書き換えは見直し候補にとどめる（「〜できる」の言い換えには正しい直しが多いため）。同じ言い方の中の言い換え（することができる → できる、してもよい → してよい）は出ない。問いの文は比べない。確度を否定する形（予定はない、可能性は低い など）は、両側で同じなら外してほかの語を比べ、片側だけなら比べない。推量の言い方が、同じ強さの別の慎重な言い方に替わっただけの文（かもしれない → 恐れがある、と思われる → 見込み）は、文の種類を表す語の候補に出さない（「■ 文の種類を表す語が変わった文」には出る）。外すのは、同じ節の同じ事柄について、主な慎重な語（ことがある、場合がある、検討、傾向、期待できる のような数えない語でないもの）に言い換えたときだけ。述語の肯定と否定が替わった文（間に合うと思われる → 間に合わない見込み）、「とは限らない」にした文、条件の形にした文（恐れがあれば）、慎重さを別の節や別の文の事柄へ移した文、同じ文のほかの慎重な語が消えた文、「らしい」を言い換えた文は、今までどおり文の種類を表す語の候補に出る。推量の語がより強い語に替わった文（かもしれない → 見込み）は、同じ文に確度の強まりの候補が出ればそちらに任せ、出なければ文の種類を表す語の候補を残す。推量の語が消えて言い切った文、慎重さを足した・弱めた文は、今までどおり文の種類を表す語の候補に出る。それ以外で同じ文の推量・意見の言い方が同じ向きに変わったときは、文の種類を表す語の候補に任せ、確度の候補を重ねない。意図しない確かさの変化なら、原文の語に戻す。

状態の語: 原文が「未定」「未確認」「調査中」「検討中」「保留」「まだ〜ていない」「予定はない」のように、まだ決まっていない・分かっていない・済んでいないと伝えていた語が、推敲後の対応する文で同じ状態の言い方（まだ決まっていません、確認が取れていません、調べているところです）に言い換えられずに消えた箇所が出て、`--fail-on=meaning-risk` に数える。確定・完了・約束の形（決まりました、修正いたしました、お届けします、影響はありません）に変えていれば、原文の状態に戻す。「調査中です → 調査しています」「未定です → 決まっておりません」のように同じ途中の状態を言い換えた形は出ない。条件の中の語（未定の場合は）、「作業中は」のような時を言う使い方、状態そのものを打ち消す言い方（未確認の項目はありません）は見ない。同じ文で否定の候補か、推量の言い方の候補が出たときは、その候補に任せる。

約束: 推敲後に、原文にない書き手の約束（〜いたします、改めてご連絡します、お送りします）、保証（追加の費用はかかりません、そのままご利用いただけます）、再発防止の誓い（再発防止に努めます、今後このようなことがないよう）が足された箇所が出て、`--fail-on=meaning-risk` に数える。原文にある約束の敬語を上げただけ（送ります → お送りいたします、出すね → 提出いたします）と、読み手への依頼の敬語（ご確認ください → ご確認をお願いいたします）と、あいさつの定型は出ない。再発防止の語は、書き手がこれから取り組む述語があるときだけ誓いとみなす（再発防止策は実施済みです、は出ない）。いたします・今後・弊社のような書き手を示す語のない普通の「〜します」（疲労を軽減します）は、説明や手順の文かもしれないので、数えない候補として出す。依頼や資料に書いてある約束なら残してよい（diff は依頼を見られないので候補に出る）。それ以外は外す（SKILL.md「情報の不増補（足さない）」）。

因果: 原文の別々の文を「〜した結果」「〜ことで」「につながった」でつないだ箇所、原文にない原因や効き目を足した箇所、原文の「〜時に」「〜際に」を「〜により」「〜ことで」と原因の言い方にした箇所も出る。`--fail-on` には数えない。原文が事実を並べていただけなら、並べたまま書く。原文の1文の「〜し、」「〜て」を「ため」と語にしただけの形は出ないが、読み手が同じつながりを読み取れるかは読んで決める。原文にない評価の語（改善、向上、好評、大切）と、一般化・勧め（他の〇〇でも同様に、望ましい）を足したことは、diff では拾わない（語の表では拾いきれなかった）。原文にない良し悪しの判断や勧めを足していないかは、読んで確かめる（SKILL.md「情報の不増補（足さない）」）。

かぎかっこの中の言葉が変わった・なくなった箇所も出る。会話、引いた言葉、項目名なら原文に戻す。強調のかぎかっこを言い換えただけなら残してよい。空白や全角・半角、感嘆符、省略記号など書き方だけの違いと、かっこを外しただけの変化と、同じかぎかっこを別の所へ動かしただけの変化は出ない。長音の「ー」の有無は言葉の違いとして出る。かぎかっこの中の句点で文が分かれる会話（「うん。そう。」）も1つのかぎかっことして見る。問いの「？」は書き方の違いとせず、残っているかを見る。この候補は `--fail-on` に数えない。

元にない気持ちの語（「ほっと」「うれしい」など）が出たら、原文に書いていない気持ちを足していないかを見て、足していれば消す（エッセイでも書き手の気持ちを作らない。SKILL.md「情報の不増補（足さない）」）。

### ■ 残した指摘の語

最終稿に直訳語（calque）と語の一覧（project_term）の指摘が残っているときに出る（冒頭の一覧のあとの「残した指摘の語:」の行と、verify の出力の5行目にも同じ語が出る）。語ごとに、その文を SKILL.md Step 2 の問いと `references/calques.md` で読み直す。書き直しに使う名前や動作、その動作をする人が原文、依頼、提供資料、文脈のどれにも書いていないか、前後の文と呼び名がそろわず同じものを指すか分からないときは、本文を残して「書き手に確かめたい点」で尋ねる。残す理由を「残したAIっぽいところ」に書くだけにはしない。問いは3点までの決まりと選び方に従い、入らない分は「ほかに N か所」に数える。直訳語の指摘で、その分野で定着した言い方か文字どおりの意味（音、実物の場所など）なら、残す理由を「残したAIっぽいところ」に書く。project_term の語は、定着していても残さない。同じ語に直訳語と語の一覧の両方の指摘があれば、語の一覧として1つにまとめて出る。本文だけを返す指定では、確かめたい点も説明も付けないので、書き直せない語は本文のまま残す。

### ■ 差分の見直し候補

- 言い回しの種類の増減（依頼・義務・評価・可能など）: 元の文の働きからずれていれば元の表現に戻す。正当な言い換えなら残して「変えたところ」に書く。
- 文の種類を表す語が変わった文（伝聞・推量・意見・例え・依頼や決まりの表現が消えた、または増えた文）: Step 1 の記録と読み比べ、種類が変わっていれば元の種類に戻す。事実・皮肉・仮定は表現からは拾えないので、候補に出なかった文も記録と読み比べる。
- 許可・能力の言い方が変わった文（してよい、できる などが、同じ文の中で消えた、増えた、ほかの言い方に替わった文）: 元の言い方に戻す。仕様書や設計文書では、許可と能力と説明と保証の違いがそのまま仕様の違いになる。
- 元の文にない語、消えた語: 勝手な付け足しや、必要な前提の脱落がないか。
- 箇条書きを地の文にした、文の数が変わった: 箇条書きを地の文にしたときに余計な評価や義務を足していないか、段落をまとめて話題が混ざっていないか。意図した改行の整理と区別し、Markdown に必要な改行や空白が見落としで消えていないか。紹介記事・宣伝文（promo）では、評価の語を短く重ねる型（安い。うまい。早い。）を1文にしていないかも見る。勢いの検査では拾えないので、1文にしていたら原文の形に戻す（doc-types/promo.md 1章）。
- つながりを確かめる場所: つなぎ言葉や指示語が前後の文と論理的につながるか。「これ」「それ」の指す先が一読で分かるか。分からなければ推測で名詞を補わず、「書き手に確かめたい点」に出す。
- 文末の種類が変わった文、文末の立場: 立場（`--stance` に渡した値）に合う向きか。候補を理由に、働きの違う文まで同じ文末にそろえない。
- 太字にならない書き方: 「■ 表現・書式の見直し候補」の lint の項と同じに扱う。

### ■ 文体の硬化

推敲の前後で、漢字の割合、名詞化の言い回し（一覧は references/lists/nominalization.txt）、漢語が「の」で3つ以上続く形が増えた箇所。文書全体の値と、1文ごとの前後が出る。示された文で、原文の和語の短い言い回しを漢語や名詞化に置き換えていないかを見て、意味が同じなら原文の言い回しに戻す。ただし、他動詞を1語だけ名詞にした語を「の」で受ける形（lint の renyo_noun。「結果の確かめ」）を漢語の名詞に直した所は、候補に出ても戻さない。仮名を漢字にしただけ（こと → 事）なら、表記の決まり（SKILL.md「用途と表記の扱い」）に合わないので元に戻す。原文がもともと硬いだけなら候補は出ない。種類が incident、formal、paper のときは参考として出るだけ（節の見出しが「■ 文体の硬化（参考 N件」になる）なので、障害報告の報告の語（発生、復旧など）や正式な言い方、論文の言い方を和語に開かない（doc-types/incident.md、doc-types/formal.md、doc-types/paper.md）。件数は確認の記録の「硬化の検査」に書く（incident、formal、paper では「参考2件」のように）。

### ■ 勢い

推敲の前後で、「！」「？」、絵文字、強める語（本当に、ぜひ、最強など。一覧は references/lists/intensifiers.txt）の数が減った行と、見出しの字数の合計が大きく減った場合。種類が promo のときは、番号つき項目の行（1. …）と太字だけの行も見出しに数える。箇条書きの太字の行（- **…**）は数えないので、見出しとして書かれていたら縮めていないかを読み比べる。減った行の前後が出る。紹介記事や宣伝文で書き手の勢いを落としていたら、原文の「！」や語、見出しの言い回しに戻す（doc-types/promo.md）。紹介記事や宣伝文で、同じ褒め言葉の繰り返しをまとめて減らしていたら、原文の繰り返しに戻す（doc-types/promo.md 1章）。強める語の一覧にない褒め言葉（絶品など）は数えないので、繰り返しが残っているかを読み比べる。同じ段落に「！」が3つ以上あっても、減らせば候補に出る（紹介記事では減らさない）。問いかけの「？」が消えて平叙の文になっていたら、文の働きが変わっているので戻す。種類を決めていないときは、絵文字は SKILL.md「装飾記号の排除と太字の表示」のとおり外し、勢いの候補は、紹介記事やエッセイではないかを確かめるきっかけにする。audience.md 1章の手がかりから紹介記事と分かれば、種類を promo にして、絵文字と勢いのある書き方を doc-types/promo.md のとおり残す。エッセイと分かっても、絵文字は外す（doc-types/essay.md 2章）。種類が pr、article、incident、manual、formal、paper のときは参考として出るだけ（節の見出しが「■ 勢い（参考 N件」になる）で、「！」や強める語を減らしたのが正しい直し方なら、そのままにする。promo 以外の種類を指定したときは、絵文字の候補も参考として出る（絵文字を外すのは決まりどおりの修正）。見出しの候補も、minutes のほかは参考として出る（見出しを短い項目名にするのは決まりどおりの修正）。minutes の見出しの候補は見直し候補のままで、議事録の推敲では見出しを変えない（domains/business.md 3章）ので、原文の見出しに戻す。mail では、絵文字と見出しの候補も見直し候補のまま出る。チャットの「！」と絵文字は書き手の口調なので、減らしていたら原文に戻す（doc-types/mail.md）。見直し候補と参考が混ざると、節の見出しは「■ 勢い（見直し候補 N件、参考 M件」になる。件数は確認の記録の「勢いの検査」に書く（参考だけなら「参考2件」、混ざれば「候補1件、参考1件」のように）。

### ■ 慎重な言い方

推敲の前後で、慎重な言い方（と考えられる、可能性がある、示唆する、の範囲では など。一覧は references/lists/hedges.txt）の数が減った文。種類によらず出る。示された文で、原文の確かさの度合いを断定（〜である、〜を示す）に変えていないかを見て、変えていれば原文の言い方に戻す。「の範囲では」のような限定を消すと、主張の範囲も広がる。同じ文で推量の言い方が消えたときは、上の「文の種類を表す語が変わった文」に出て、この節には重ねて出ない。同じ文で確度の強まりの候補が出たときも、この節には重ねて出ない。分けた文の後ろに語が残ったときと、文を動かしただけのときは出ない。一覧の語と同じ文字の並びだけを数えるので、「示唆した」「示唆される」のように形の変わった語が減っても出ない。候補がなくても読み比べる。論文と研究レポート（paper）では特に、断定を弱める向きにも変えない（doc-types/paper.md）。この節の候補は `--fail-on` に数えない。

### ■ 動かしてはいけない値

推敲の前後で、宛名（〇〇様、〇〇さん。行頭や宛先の欄にあるもの）と、リンクでないメールアドレスが、消えた、増えた、変わった箇所。種類によらず出る。宛名の「様」を「さん」にした、宛名を消したなら、原文に戻す（doc-types/mail.md）。本文の中の「田中さんは」のような言及は見ない。数字と単位、日時、URL、引用の書き方の変化は ■ 意味が変わる恐れ に出る（run の「値の検査」の行では「意味が変わる恐れ N件」と数える）。この節の候補は `--fail-on` に数えない。

### ■ 敬語の度合い

`--doc-type mail` のときだけ出る。推敲の前後で、1文あたりの敬語の数（いただく、くださる、申し上げる、存じます、させていただく）か、文末の「です・ます」の割合（「だ・である」との比）が20ポイント以上動いた文書の候補。示された文の前後を読み、「〜いただけますでしょうか」を「〜してください」にしたように度合いを変えていれば、原文の言い方に戻す。ただし、依頼で書き手と読み手との関係を言われ、persona.md 7章の範囲で上げた所は戻さない。二重敬語を直した結果（ご確認させていただきました → 確認いたしました）で、度合いが同じなら残し、「変えたところ」に書く。チャットの口語を「です・ます」にそろえていたら戻す（doc-types/mail.md）。文書全体の割合で見るので、どの文で変わったかは全文差分で確かめる。「ください」も「くださる」に数えるので、「〜いただけますでしょうか」を「〜してください」にしても数は変わらない。文末の割合は「です・ます」と「だ・である」の文だけで数え、チャットの口語の文末（〜かも、〜しときます）は入らない。この2つの書き換えでは候補が出ないので、候補がなくても原文と読み比べる。この節の候補は `--fail-on` に数えない。

### ■ 文体の切り替え

常体から敬体、または敬体から常体へ変わった文が3文以上あり、原文のその文体の文の5割以上を占めるときに出る。いくつかの文を1文に合わせて文体を変えたときも、合わせた文を数える。引用ブロックと会話の行（「」『』だけの行）は数えない。「下さい」と「ください」は同じ文体に数える。原文の主な文体を変えた候補（switched）は、意図した切り替えでなければ原文の文末に戻す。原文で揺れていた文末を多いほうにそろえた候補（unified）は、そのまま残してよい。読み手に合わせて意図して変えたなら残し、「変えたところ」に書く。`--reader` の指定で判定は変わらない。mail で「です・ますの割合」の候補があるときは、■ 敬語の度合い に任せて重ねない。この節は状態の候補数と `--fail-on` に数えない。

### ■ 表現・書式の見直し候補

- 文脈に合う専門用語や事実の記述は、無理に言い換えない。「大事です」のような評価を担う語や、主張に必要な否定（AではなくB）は残す。
- 太字にならない書き方: 元の太字が表示されるかを確かめ、すでに表示される書き方なら変えない。直すときは、太字の範囲や前後の文が崩れないかを確かめ、不確かな案はそのまま当てずに目で整える。意味は変わらないので「変えたところ」には書かない。
- `--doc-type` を付けたときは、その種類で普通な書き方を拾う規則の候補を lint が外し、外した件数だけを出す（中身は `--doc-type` を付けずに実行すると見られる）。外れるのは種類の表の範囲だけで、ほかの型は SKILL.md 1章のとおりに確かめる。
- 過剰な箇条書きの候補（excess_list）は、行頭から書いた `<details>` と `</details>` の間の箇条書きを、比率の分子にも分母にも数えない（中に多く畳んでも、外の箇条書きの比率は薄まらない。中に箇条書きがあれば、候補に「（<details> の中の箇条書きN行は数えていません）」と添える）。畳んだ中の箇条書きも、論理を分断していないかは SKILL.md の Step 2 の9のとおりに読む。
- 同じ文末が続くという候補は、読みにくさを見直すきっかけにとどめる。AIの文の目印として扱わず、語尾を散らすために文の働きや時制を変えない（gemini-syntax.md 原則8）。
- 2.2.0 で足した info の指摘（calque、metaphor_label、say_hedge、thin_evaluation、katakana_term、dialogue_period、narrative_density、copy_comma_noun、bare_verb_chain、project_term）は、直す合図ではなく、文脈を読み直すための候補。指摘が出ただけでは直さず、語を残すこともある。直すときは、誰が何をどうするかを文として書き直す（SKILL.md Step 2）。点数（rule_penalty_score）には入らない。
  - calque（直訳語。message に型の番号と当たった言い方）と project_term（語の一覧の flag.txt の語。message にその語）: `references/calques.md` の問いで確かめる。1行に1件なので、message に並んだ言い方を一つずつ確かめる。project_term の語は、定着していても1つ目の問いで残さない（SKILL.md Step 1）。
  - metaphor_label: SKILL.md「案内用の見出し」。say_hedge: slop-catalog.md 6章「文末の付け足し」。thin_evaluation、katakana_term: slop-catalog.md 5章。copy_comma_noun: SKILL.md「コピー調の抑制」。bare_verb_chain: SKILL.md「主語と目的語の明確化」。

### ■ 資料との照合

道具が照らすのは数値、名前、語、確度の語だけ。主張、条件、担当、未確認の事項が資料どおりかは、Step 1 の記録と最終稿を読み比べる。資料にない語は、足した事実でないかを確かめる。資料にあった確度の語（未確認、予定など）が最終稿から消えていないかも見る。

新規作成では、下書きと最終稿だけを比べず、資料と最終稿を読み比べる。資料にない数値と名前、資料にない担当や条件を足していないかを確かめる。

会話やファイルから補った値（`references/fact-recovery.md`）が「資料にない数値・名前」に出たら、抜き書きの行と読み比べ、同じ値と主張の行がなければ補う前に戻す（SKILL.md「情報の不増補」の、相対の日付に添えた日付は除く）。「単位のない数とだけ一致」の行は、設定の行（`名前 = 数`）を根拠にした値を見せるだけで、根拠であることは示さない（`retry_wait = 3` を回数の3回にする取り違えもここに出る）。「資料に基づく補足の候補」の行も根拠の確認ではない。「資料にあった確度の語が最終稿にない」に値が添えてあれば、その値の文の確度を資料に合わせる。■ 事実の穴の候補 の節は一部だけで、候補にない穴もある。

### ■ 全文差分

推敲の対象外の箇所（コード、引用、表など）も含めて、意図しない変化がないかを見る。全文差分は変わった箇所を示すだけで、意味が同じだという証明ではない。

## 3. 候補に出なくても確かめること

- 文書の用件と段落: 個々の文の時制を分けたり語尾の種類を数えたりせず、読み手の立場で段落を通読する。用件を果たしているか、誰が何をするかが自然に伝わるか（語尾の種類の数やばらつきは基準にしない）。変更報告では、どの文から書き手が何をどう改めたと読み取れるか。仕組みの説明や現在の方針・動作が用件ならその内容を残し、段落の目的に合う文末や正当な時制の混在は保つ。
- 構造: 誰が何をどの条件で行うか、修飾先、例外・否定・限定・数量、並列や出来事の順を元と読み比べ、関係を見失う箇所や読み戻る箇所が減ったか。助詞や語順を変えた箇所では、対象となる人や場面、条件がそろえば行うことと、その条件のときだけ行うことの区別が保たれているか。
- 本文内の反復: 同じ段落で一つの問題や結果を長く言い直していないか。指示語で受けられる重複は整理し、複数の対象を区別するための再掲は残す。種類が promo のときの同じ褒め言葉の繰り返しは、反復として整理せずに残す（doc-types/promo.md）。
- 名詞と説明文: 本文と「変えたところ」などの説明の欄で、語が指す役割に合っているか。元にない信頼性・唯一性・約束を足していないか。

## 4. 目視の点検（Python を実行できないとき）

原文と最終稿（新規作成では資料と最終稿）を次の観点で読み比べる。確認の記録には「実行した検査: なし」、「実行しなかった検査: lint、diff、最終稿の照合（Python を実行できないため。観点を目で点検した）」と書き、状態の行は `yomiyasu-check: not_run reason=no_python` にする。新規作成では diff の代わりに資料との照合を挙げる。

- 数値、日付、固有名詞、否定、条件、例外、確度（見込み → 予定、と思われる → 断定のような確かさの変化）、実施済みと未確認の区別、状態の語（未定、調査中）が残っているか、原文にない約束・保証・再発防止の誓い・因果・評価・勧めを足していないか
- だれが何をするか（主語、目的語、使役の相手）
- 文の種類と言い回しの種類（伝聞、推量、意見、例え、依頼、義務、評価、可能）
- 元にない語、消えた語
- 文書全体の用件と段落の目的、変更報告で改定の内容が読み取れるか、文末が立場に合うか
- 段落と箇条書きの変化、つなぎ言葉と指示語のつながり
- コード、引用（かぎかっこの中の会話や引いた言葉も含む）、URL、表やスキーマの名称
- 太字が表示される書き方か
