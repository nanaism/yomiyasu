# 検査の出力の見方と目視の点検

SKILL.md の手順5で `yomiyasu_check.py run` の出力の候補を確かめるときに読む。Python を実行できないときは4章の目視の点検に従う。

候補は直す指示ではなく、原文（新規作成では資料）に照らして確かめる箇所。候補を消すためだけに言い換えを繰り返さない。直すのは1回までで、直したら run をもう一度実行する（SKILL.md の手順5）。候補が出ないことも、意味が保たれたことの証明ではない。lint は点数を出さない。候補の数を品質の合格点として扱わない。

## 1. 出力の始めの行

- 1行目は次にすることを示す。そのとおりに進める。lint、diff、資料との照合の候補が0件でも、文体の硬化と勢いの見直し候補があれば、1行目は「その節を原文と照らし」と案内するので、■ 文体の硬化 と ■ 勢い の節を原文と読み比べる。
- 2行目は状態の行（`yomiyasu-check:` で始まる行）。完了報告の確認の記録に写す。提出の前に verify を実行したときは、verify の出力の2行目を写す。
- 3行目は実行した検査の要約で、完了報告の「実行した検査」に対応する。diff の「候補N件」には、文体の硬化と勢いの候補を数えない（次の2行と、それぞれの節に出る）。diff だけを実行したときも同じで、状態の行の末尾に「（文体の硬化と勢いの見直し候補 N件は下の節）」が添えられる（最後の状態の行では「上の節」）。
- 記録の行のあとに「硬化の検査: 候補なし」「勢いの検査: 参考1件」のような2行が出たら、値を完了報告の同じ名前の行に写す（参考だけなら「参考N件」、見直し候補と参考が混ざれば「候補N件、参考M件」になる）。diff を実行しなかったときなど、この2行が出なければ、完了報告にも2行を書かない。

## 2. 出力の節ごとの見方

### ■ 意味が変わる恐れ

数値、否定、「が」「を」などの入れ替え、問いの文、文の種類の印、コード・URL・引用、資料にない数値や名前が変わった箇所。原文と資料に照らし、意図しない変化は元に戻す。資料に基づく訂正なら残し、「変えたところ」に「（資料に基づく補足）」と書く。

否定されていた語が、否定のない文に「目的」「重視」「まず」などの語と一緒に出た箇所（見出しと「Aは使わず」「Aはせず」では、A を肯定した節に出た箇所）と、「AだけでなくB」「AとB」のように B と並べて肯定された箇所（否定対比の逆転）もここに出る。否定対比を直したときに、否定していた側が目的や優先の側へ移っていないかを確かめ、移っていれば主張が逆になっているので原文の否定に戻す（rephrase-test.md 3章）。「まず、Aを減らす」「まず、Aを自動化する」のように A を減らす・変える推敲でも候補に出ることがあるので、A が目的や優先の側に移ったのか、減らす・変える側のままかを読んで決める（側が変わっていなければ、そのままでよい）。拾えない形もあるので、候補がなくても否定対比を直した箇所は読み比べる。

元にない気持ちの語（「ほっと」「うれしい」など）が出たら、原文に書いていない気持ちを足していないかを見て、足していれば消す（エッセイでも書き手の気持ちを作らない。SKILL.md 4.2）。

### ■ 差分の見直し候補

- 言い回しの種類の増減（依頼・義務・評価・可能など）: 元の文の働きからずれていれば元の表現に戻す。正当な言い換えなら残して「変えたところ」に書く。
- 文の種類の印が変わった文（伝聞・推量・意見・例え・依頼や決まりの表現が消えた、または増えた文）: 手順2のメモと読み比べ、種類が変わっていれば元の種類に戻す。事実・皮肉・仮定は表現の印では拾えないので、候補に出なかった文もメモと読み比べる。
- 元の文にない語、消えた語: 勝手な付け足しや、必要な前提の脱落がないか。
- 箇条書きを地の文にした、文の数が変わった: 箇条書きを地の文にしたときに余計な評価や義務を足していないか、段落をまとめて話題が混ざっていないか。意図した改行の整理と区別し、Markdown に必要な改行や空白が見落としで消えていないか。紹介記事・宣伝文（promo）では、評価の語を短く重ねる型（安い。うまい。早い。）を1文にしていないかも見る。勢いの検査では拾えないので、1文にしていたら原文の形に戻す（doc-types/promo.md 1章）。
- つながりを確かめる場所: つなぎ言葉や指示語が前後の文と論理的につながるか。「これ」「それ」の指す先が一読で分かるか。分からなければ推測で名詞を補わず、「書き手に確かめたい点」に出す。
- 文末の種類が変わった文、文末の立場: 立場（`--stance` に渡した値）に合う向きか。候補を理由に、働きの違う文まで同じ文末にそろえない。
- 太字にならない書き方: 「■ 表現・書式の見直し候補」の lint の項と同じに扱う。

### ■ 文体の硬化

推敲の前後で、漢字の割合、名詞化の言い回し（一覧は references/lists/nominalization.txt）、漢語が「の」で3つ以上続く形が増えた箇所。文書全体の値と、1文ごとの前後が出る。示された文で、原文の和語の短い言い回しを漢語や名詞化に置き換えていないかを見て、意味が同じなら原文の言い回しに戻す。仮名を漢字にしただけ（こと → 事）なら、表記は直さない決まり（SKILL.md 冒頭）なので元に戻す。原文がもともと硬いだけなら候補は出ない。種類が incident か formal のときは参考として出るだけ（節の見出しが「■ 文体の硬化（参考 N件」になる）なので、障害報告の報告の語（発生、復旧など）や正式な言い方を和語に開かない（doc-types/incident.md、doc-types/formal.md）。件数は完了報告の「硬化の検査」に書く（incident と formal では「参考2件」のように）。

### ■ 勢い

推敲の前後で、「！」「？」、絵文字、強める語（本当に、ぜひ、最強など。一覧は references/lists/intensifiers.txt）の数が減った行と、見出しの字数の合計が大きく減った場合。種類が promo のときは、番号つき項目の行（1. …）と太字だけの行も見出しに数える。箇条書きの太字の行（- **…**）は数えないので、見出しとして書かれていたら縮めていないかを読み比べる。減った行の前後が出る。紹介記事や宣伝文で書き手の勢いを落としていたら、原文の「！」や語、見出しの言い回しに戻す（doc-types/promo.md）。紹介記事や宣伝文で、同じ褒め言葉の繰り返しをまとめて減らしていたら、原文の繰り返しに戻す（doc-types/promo.md 1章）。強める語の一覧にない褒め言葉（絶品など）は数えないので、繰り返しが残っているかを読み比べる。同じ段落に「！」が3つ以上あっても、減らせば候補に出る（紹介記事では減らさない）。問いかけの「？」が消えて平叙の文になっていたら、文の働きが変わっているので戻す。種類を決めていないときは、絵文字は SKILL.md 4.4 のとおり外し、勢いの候補は、紹介記事やエッセイではないかを確かめるきっかけにする。audience.md 1章の手がかりから紹介記事と分かれば、種類を promo にして、絵文字と勢いのある書き方を doc-types/promo.md のとおり残す。エッセイと分かっても、絵文字は外す（doc-types/essay.md 2章）。種類が pr、article、incident、manual、formal のときは参考として出るだけ（節の見出しが「■ 勢い（参考 N件」になる）で、「！」や強める語を減らしたのが正しい直し方なら、そのままにする。promo 以外の種類を指定したときは、絵文字の候補も参考として出る（絵文字を外すのは決まりどおりの直し）。見出しの候補も、minutes のほかは参考として出る（見出しを短い項目名にするのは決まりどおりの直し）。minutes の見出しの候補は見直し候補のままで、議事録の推敲では見出しを変えない（domains/business.md 3章）ので、原文の見出しに戻す。見直し候補と参考が混ざると、節の見出しは「■ 勢い（見直し候補 N件、参考 M件」になる。件数は完了報告の「勢いの検査」に書く（参考だけなら「参考2件」、混ざれば「候補1件、参考1件」のように）。

### ■ 表現・書式の見直し候補

- 文脈に合う専門用語や事実の記述は、無理に言い換えない。「大事です」のような評価を担う語や、主張に必要な否定（AではなくB）は残す。
- 太字にならない書き方: 元の太字が表示されるかを確かめ、すでに表示される書き方なら変えない。直すときは、太字の範囲や前後の文が崩れないかを確かめ、不確かな案はそのまま当てずに目で整える。意味は変わらないので「変えたところ」には書かない。
- `--doc-type` を付けたときは、その種類で普通な書き方を拾う規則の候補を lint が外し、外した件数だけを出す（中身は `--doc-type` を付けずに実行すると見られる）。外れるのは種類の表の範囲だけで、ほかの型は SKILL.md 4章のとおりに確かめる。
- 過剰な箇条書きの候補（excess_list）は、行頭から書いた `<details>` と `</details>` の間の箇条書きを数えない（中に箇条書きがあれば、候補に「（<details> の中の箇条書きN行は数えていません）」と添える）。畳んだ中の箇条書きも、論理を分断していないかは SKILL.md 4章のとおりに読む。
- 同じ文末が続くという候補は、読みにくさを見直すきっかけにとどめる。AIの文の目印として扱わず、語尾を散らすために文の働きや時制を変えない（gemini-syntax.md 原則8）。

### ■ 資料との照合

道具が照らすのは数値、名前、語、確度の語だけ。主張、条件、担当、未確認の事項が資料どおりかは、手順2で書き出したメモと最終稿を読み比べる。資料にない語は、足した事実でないかを確かめる。資料にあった確度の語（未確認、予定など）が最終稿から消えていないかも見る。

新規作成では、下書きと最終稿だけを比べず、資料と最終稿を読み比べる。資料にない数値と名前、資料にない担当や条件を足していないかを確かめる。

### ■ 全文差分

推敲の対象外の箇所（コード、引用、表など）も含めて、意図しない変化がないかを見る。全文差分は変わった箇所を示すだけで、意味が同じだという証明ではない。

## 3. 候補に出なくても確かめること

- 文書の用件と段落: 個々の文の時制を分けたり語尾の種類を数えたりせず、読み手の立場で段落を通読する。用件を果たしているか、誰が何をするかが自然に伝わるか（語尾の種類の数やばらつきは基準にしない）。変更報告では、どの文から書き手が何をどう改めたと読み取れるか。仕組みの説明や現在の方針・動作が用件ならその内容を残し、段落の目的に合う文末や正当な時制の混在は保つ。
- 構造: 誰が何をどの条件で行うか、修飾先、例外・否定・限定・数量、並列や出来事の順を元と読み比べ、関係を見失う箇所や読み戻る箇所が減ったか。助詞や語順を変えた箇所では、対象となる人や場面、条件がそろえば行うことと、その条件のときだけ行うことの区別が保たれているか。
- 本文内の反復: 同じ段落で一つの問題や結果を長く言い直していないか。指示語で受けられる重複は整理し、複数の対象を区別するための再掲は残す。種類が promo のときの同じ褒め言葉の繰り返しは、反復として整理せずに残す（doc-types/promo.md）。
- 名詞と説明文: 本文と「変えたところ」などの説明の欄で、語が指す役割に合っているか。元にない信頼性・唯一性・約束を足していないか。

## 4. 目視の点検（Python を実行できないとき）

原文と最終稿（新規作成では資料と最終稿）を次の観点で読み比べる。完了報告では「実行した検査: なし」、「実行しなかった検査: lint、diff、最終稿の照合（Python を実行できないため。観点を目で点検した）」と書き、状態の行は `yomiyasu-check: not_run reason=no_python` にする。新規作成では diff の代わりに資料との照合を挙げる。

- 数値、日付、固有名詞、否定、条件、例外、確度、実施済みと未確認の区別
- だれが何をするか（主語、目的語、使役の相手）
- 文の種類と言い回しの種類（伝聞、推量、意見、例え、依頼、義務、評価、可能）
- 元にない語、消えた語
- 文書全体の用件と段落の目的、変更報告で改定の内容が読み取れるか、文末が立場に合うか
- 段落と箇条書きの変化、つなぎ言葉と指示語のつながり
- コード、引用、URL、表やスキーマの名称
- 太字が表示される書き方か
