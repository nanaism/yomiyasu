# 出力の欄と、情報が足りないときの書き方

SKILL.md の手順3で、情報が足りないとき、説明の欄や「書き手に確かめたい点」の書き方に迷ったときに読む。返答の形（欄の名前と順）と確認の記録は SKILL.md 3章のとおり。

## 1. 出力の形を確かめる

- 最終出力の前に、依頼にある出力形式の指定を確かめる。
- 本文だけを返す指定があれば、変えたところ、残した点、質問、編集者向けの注記は別の欄に出さず、内部の確認にとどめて本文だけを返す。環境の指定で構造化された形式が必要なときも、編集者向けの欄を空にできる形式なら空にして、本文だけの指定を守る。確認の記録の扱いは SKILL.md 3章。
- 指定のない通常の対話では、SKILL.md 3章の形で、本文のあとに必要な説明や質問を添える。
- 説明の欄にも、絵文字や不要なカッコを使わない（gemini-syntax.md 原則10、原則12）。

## 2. 書き直した本文

- 読み手に渡す本文だけを置く。原文にある主張と、原文が読者に伝えている「未定」「調査中」の状態を残し、見出しや箇条書きなどの書式は保つ。
- 推敲側が意味を読み取れないことの注記や説明、書き手への質問は本文に入れない（編集の印を挟まないことは SKILL.md 4.2）。
- 本文をコードの囲みに入れない。

## 3. 変えたところ

- 意味が動きやすい変更、つながりを直したところ、文末を立場に合わせてそろえたところ、補った語、資料に基づく補足だけを、5点まで書く。なければ「なし」と1行で書く。
- 形は「元の表現 → 書き直し後の表現（変更理由）」。その書き方を選んだ短い理由も含める。
- 文末をそろえた箇所は1行にまとめる（stance-and-endings.md 9章）。
- 表示されない太字を表示される書き方に直しただけの箇所は書かない。意味が変わらないため（gemini-syntax.md 原則14）。
- 言い直しテスト（SKILL.md 手順3）で案を捨てて残した箇所は、ここに書かない。

## 4. 残したAIっぽいところ

- 言い直しテスト（SKILL.md 手順3）で案を捨てた箇所を書く。前置き、結び、内面の説明を意味や重みのために残したときも、ここに書く。なければ見出しごと出さない。
- 残した表現と、残した理由（言い直すと何が変わるか）を1行で書く（rephrase-test.md 4章）。原文に根拠のない重大さなどの比較の基準を決めたり、残した表現により狭い具体的な意味を決めつけたりしない。
- 予告の文を中身とまとめると意味が変わるので残したときも、ここに書く（gemini-syntax.md 原則13）。エッセイの内面の説明の扱いは domains/essay.md 2章。
- エッセイ、小説、紹介記事・宣伝文と判断して、書き手の比喩や勢いを個性として残したときは、1つずつここに並べず、本文とは別に、利用者への補足として完了報告の最後に判断の一言を書く（「エッセイと判断したので、文の個性を残しました」「紹介記事・宣伝文と判断したので、勢いのある書き方を残しました」。doc-types/essay.md と promo.md の3章）。

## 5. 書き手に確かめたい点

- 意味、条件、用途などが分からず、本文を確定するのに確認が要るときだけ、2点まで書く。なければ見出しごと出さない。
- 紹介記事の根拠のない誇張（doc-types/promo.md 2章）は、本文を書き換えずに残すときも根拠を尋ねる。本文を確定するのに要る確認として、2点の中に数える。
- 未確定の内容と、それが本文にどう影響するかを短く書く。説明が要るときは、何が読み取れず何を確かめたいかを短く述べてから尋ねる。同じ説明をほかの欄で繰り返さない。
- 確認の問いでも、不明な語が何を指すかを推測で前提にしない。判断条件や特定の責務など、語の種類や役割を勝手に限定して尋ねない。文脈に根拠のない未確定の動作についても、状態や行き先などを決めつけず、何が分からないかを中立に尋ねる。
- 説明すると述べた関係が読み取れないときは、どの内容とどの内容の対応が分からないかも含める。用語の指す対象だけを尋ねて、その関係を省かない。
- 出典の示されていない「〜という声もあります」は本文に残す。出典の有無が主張の受け取り方を左右するときだけ、出典があるかを尋ねる。
- 元から未定や調査中であることと、提供された情報から読み取れないこととを区別して尋ねる。些細な不足を機械的に並べない。
- 提供済みの文脈を聞き直さない。意味を保って残せる表現を削るかどうかという、好みの問いは出さない。
- 文書の立場を決めきれないときに、もう一方の立場の文末を示す書き方は stance-and-endings.md 9章。
- 読者に合わせて説明が要る所（「ここに説明が必要です: 語（場所）」）は、この2点とは別に3点まで書く。書き方は audience.md 10章。

## 6. 情報が足りない場合の暫定文

- 文の意味、働き、条件や主張を確定するのに必要な内容が読み取れず、確定した本文を書けない場合に限り、分かる内容で暫定の本文を書く。
- 本文には、原文の主張、否定、条件、言い切りの強さ、適用範囲、文が何のために書かれているかと、原文が読者に伝えている「未定」「調査中」の状態を残す。動作主と条件も、必要な書式とともに残す。
- 主張を確認の欄で引用したり、「〜と述べている」のように伝聞や批評に変えたりするだけでは、本文で主張を保ったことにならない。
- 意味を確定できない表現でも、結びつく動作が分かるなら、元にない対象や仕組みを推測で書き足さずに本文に残す。すべての表現を一字一句残す必要はなく、意味の幅を変えずに自然な文へ整える。
- 意味を読み取れないことと、仕様や予定が実際に未定なことは分ける。原文や文脈にある「未定」「調査中」は、その時点の状態として保つ。分からない主体、動作、手段は補わず、読んでいない外部の資料を調べたかのような説明もしない。
- 作者の氏名などが分からなくても、本文の意味や働きに影響しなければ、それだけで本文全体を暫定の扱いにしない。意味や働きに影響しない実装の細部の不足まで、機械的に暫定の扱いにしたり並べたりしない。
- 読み取れないことを書き手に伝える言い方（「提供情報からは」「確認できません」など）は、強制も禁止もせず、文脈に合わせて短く自然に書く。原文が読者に伝えている記述にその言い方があれば、本文に保つ。
- 依頼か説明か決まらない文も、働きを決めずにこの書き方に従う（stance-and-endings.md 10章）。

## 7. 説明の欄でも足さない

- 足さない規則（SKILL.md 4.2）は、本文だけでなく、変えたところ、残したAIっぽいところ、書き手に確かめたい点のすべての欄に当てはめる。
- 本文で元の表現を残したときも、説明の欄で、示されていない比較の基準（重大さなど）を決めたり、より狭い具体的な意味を決めつけたりしない。
- 変更理由や確認事項でも、不明な語を判断条件など特定の役割だと決めつけず、元にない約束、制約、信頼性を感じさせる語に言い換えない（slop-catalog.md 5章）。
- 自分で書く見出し、変更理由、確認事項にも、専門用語と名称の基準（slop-catalog.md 2章）と、コピー調を持ち込まない決まり（gemini-syntax.md 原則16）を当てはめる。
