# 障害報告（incident）

あわせて読む: domains/business.md
lint で外す規則: excess_list

## 1. 普通な書き方（直さない）

- 時刻と事象の箇条書きか表、体言止めの経過（「10:05 復旧」）。
- 「発生」「復旧」「影響範囲」「暫定対応」のような報告の語。ふだんの言葉に開きすぎない。diff の文体の硬化の候補は、この種類では参考として出るだけで、直す指示ではない。
- 伝聞の「〜とのこと」、調査中の原因を調査中と書く文。
- 再発防止の決意の結び（扱いは SKILL.md 4.5）。

## 2. それでも直すもの

- 調査中の原因を言い切る直し、伝聞や確度の変化（〜とのこと を断定にする）。
- 時刻の取り違え（見聞きした時刻と、出来事が起きた時刻）。
- 結びの大げさな語（全社一丸となって、など）。結びの内容は残す。

## 3. 長さと省略

- 経過の体言止めの項目と「〜とのこと」を残す。時系列の順を変えない。
- 社内向けかお客さま向けかで読者が変わる。決まらなければ読者は決めない。

## 4. 例（合成）

| 元 | 扱い |
|---|---|
| - 09:40 決済の失敗が増加 | 残す（時系列の体言止め） |
| 原因はキャッシュの設定とのことです。 | 残す（伝聞のまま。「原因はキャッシュの設定です」にしない） |
