# 直訳語の見方と書き直し方

SKILL.md Step 2 の直訳語の問いの細目。lint は、この型に当たった文に `calque`（info）の印をつける。印は直す合図ではなく、文脈を読み直すための候補で、印がついただけでは直さない。

## 1. 3つの型

- 型1: 機械やシステムが主語なのに、人や物の動作の動詞を使っている文（拾う、引く、通る、効く、響く、足す など）。
- 型2: 実物の名前の代わりに、場所のたとえを使っている名詞（入口、受け口、口、〜先 など）。「理解の入口」のような抽象的な話の入り口は slop-catalog.md 3章の「役割・位置の比喩」で見る。
- 型3: 英語の言い方を一語ずつ写した句（「足すものがない」は add value、「失効が効く」は take effect、「〜ときに効くのは」は what matters）。英語の構文ごと写した文は slop-catalog.md 2章で見る。

## 2. 直すかどうかの問い

- その分野の人が、自分で書くときに使う呼び名か。
- 英語に戻すと、一語ずつ英語の言い方に対応するか。

1つ目は、話して通じるかではなく、その分野の人が仕様や手順書に書くときにその言い方を選ぶかで問う。1つ目に「はい」なら残す（flag.txt の語は除く）。2つ目に「はい」で、1つ目に「いいえ」なら書き直す候補にする。

## 3. 残す言い方

- 定着した言い方: テストが通る、キャッシュが効く、薬が効く、ブレーキが効く、駅の入口、人が落とし物を拾う、パッケージの依存先。lint はこれらに印をつけない。
- 「依存先」は、パッケージの依存関係の意味でも、つないでいる外部のサービスの意味でも残す。
- 語の一覧の `flag.txt` の語は、この節の残す言い方や辞書の訳語の名詞に当たっても残さない（SKILL.md Step 1）。印は `project_term` で、4章のとおり書き直すか尋ねる。替える名前が原文、依頼、提供資料、文脈のどれにもなければ、「〜もの」「〜こと」のような広い言い方に替えず、本文を残して尋ねる。
- 語の一覧の `allow.txt`（`.yomiyasu-words/`）の語は、そのプロジェクトで定着した言い方として残す。lint も印を外す。
- 辞書の訳語を当てた名詞（要求、承認、事実、影響 など）は、この型では見ない。

## 4. 書き直し方

- 型に当たった文では、誰が何をどうするかを原文と前後の文から確かめ、その関係が読める文に書き直す。語を1つ別の語に替えるだけでは、文の組み立てが変わらないので直らない。
- 印のついた語の中身は、すぐ後ろの文に書いてあることが多い（「この経路は、〜が〜を呼ぶときだけ使う」「ここでの〜は、〜のことです」）。その中身を主語や目的語、条件にして書き直し、後ろの文は同じことを2回書くときだけまとめる。まとめるときは、後ろの文の範囲の語（だけ、すべて など）を落とさない。印のついた語を、言い換えの語（カタカナ語、「〜ごと」など）や、何が起きるかを言わない意味の広い語（影響する、及ぶ、支障が出る、関わる、左右する）に替えるだけにはしない。何がどうなるかが後ろの文に書いてあれば、その中身で書く。広い語に替えた句を、その中身と並べて残すこともしない。
- 見出しに印のついた語（flag.txt の語を含む）があるときは、SKILL.md「案内用の見出し」のとおり本文の語で項目名を作り、元の見出しが言っていた目的（料金を見積もる前に確かめる点 など）を項目名に残す。本文の題目を並べただけの名前にはしない。
- 型3の句は、元の英語の言い方の意味で書き直す。字面の語（足す、効く）を同じ字面の別の語（加える、効き目）に替えるだけにしない。「足すものがない」は、中継や層を足しても得られる利点がない、という評価の文のことが多い。前後の文が加える項目や材料の話なら、何も加えないという事実の文として残す。「〜ときに効くのは、次の〜です」は、そのときに大事なことを並べる前置きで、何かに関わる・左右するという文ではない。
- 書き直しに使う名前（エンドポイント、URL、リクエスト など）と動作、その動作をする人は、原文（前後の文を含む）、依頼、提供資料、文脈に書いてあるときだけ使う。分からなければ本文を残し、「書き手に確かめたい点」に出す。
- 印のついた語と、その中身を書いた前後の文とで呼び名がそろわず、同じものを指すか分からないときは、本文を残し、指すものを「書き手に確かめたい点」で尋ねる。
- 言い直しテストの6点（とくに誰が誰にするか）を変えない。
- 重なる決まり: 比喩に使った動詞は SKILL.md「比喩動詞の具体化」、非生物に感情や意志を持たせた文は「擬人化の解消」、不自然な直訳の用語は「専門用語と名称の扱い」に従う。

## 5. 例（合成）

| 元 | 前後の文 | 扱い |
|---|---|---|
| 取りこぼした通知は、翌朝の再送ジョブが拾います。 | 前の文に「送信に失敗した通知は一覧に残す」とある | 送信に失敗して一覧に残った通知は、翌朝の再送ジョブがもう一度送ります。 |
| 取りこぼした通知は、翌朝の再送ジョブが拾います。 | 通知の扱いを書いた文がない | 本文を残し、再送ジョブが何をするかを「書き手に確かめたい点」で尋ねる |
| 社外からの接続は、この入口を通ります。 | 前の段落に「社外からの接続は、ロードバランサーが受けて内部のサーバーに渡す」とある | 社外からの接続は、すべてこのロードバランサーが受けて、内部のサーバーに渡します。 |
| 社外からの接続は、この入口を通ります。 | 入口が何を指し、そこで何をするかを書いた文がない | 本文を残し（受けて渡す動作を足さない）、この入口が何を指し、そこで何をするかを「書き手に確かめたい点」で尋ねる |
| 新しい鍵に替えると、古い鍵の失効が効きます。 | 前の文に「鍵を替えた時点で古い鍵は使えなくなる」とある | 新しい鍵に替えると、その時点で古い鍵は使えなくなります。 |
| 機械どうしのやり取りは、専用の回線に分けています。 | 後ろの文に「この回線は、倉庫の端末が在庫サーバーに数を送るときだけ使う」とある | 倉庫の端末が在庫サーバーに数を送る通信は、専用の回線に分けています。 |
| アプリは毎ターン、会話の履歴を読み直します。 | 後ろの文に「ここでのターンは、利用者が質問を1つ送ることです」とある | アプリは、利用者が質問を1つ送るたびに、会話の履歴を読み直します。（後ろの文はまとめる） |
| 依存先の決済サービスが止まると、注文を受けられません。 | flag.txt に「依存先」がある。後ろの文に「今呼び出しているのは決済サービスだけ」とある | 呼び出している決済サービスが止まると、注文を受けられません。 |
| 料金を見積もるときに効くのは、次の二つです。 | 後ろの文に「見積もる前に、この二つを確かめてください」とある | 料金を見積もるときに大事なのは、次の二つです。（評価の文なので、後ろの依頼の文は残す） |
| 集計を毎時回すと、全店舗に響きます。 | 後ろの文に「毎時の集計のあいだは、全店舗のレジの画面の表示が遅くなる」とある | 集計を毎時回すと、そのあいだは全店舗のレジの画面の表示が遅くなります。（後ろの文はまとめる） |
| 集計を毎時回すと、全店舗に響きます。 | 何がどうなるかを書いた文がない | 本文を残し（「影響します」に替えない）、何が起きるかを「書き手に確かめたい点」で尋ねる |
| この層で変換しても、足すものがありません。 | 前の文に「受け取った値をそのまま次の層へ渡している」とある | この層で変換しても、得られる利点はありません。（前の文は残す。原文にない「ので」でつながない） |
| 変更を入れたら、テストが通るかを見てください。 | | 残す（定着した言い方） |
